# 찰떡 — Product Requirements Document

> 개떡같이 말해도 찰떡같이 알아듣는다.
> 주민센터·구청 등 공공기관에 민원을 내기 전에, 민원인이 필요한 민원에 대해 편하게 말하면 AI가 질문과 답으로 빠진 내용을 채워 담당자가 잘 알아들을 수 있는 요약으로 정리해 주는 휴대폰 웹앱(PWA).

# Overview

## 컨셉: AI 외지부
외지부는 조선시대에 글을 모르는 백성을 위해 민원을 대필해 주던 사람이다. 찰떡은 그 역할을 AI로 옮긴다. 민원인은 버튼을 누르고 말만 하고, 찰떡은 그 말을 담당자가 바로 쓸 수 있는 요약으로 만든다. 목적은 민원인이 질 좋은 민원 처리를 받게 하는 것이다.

## 서비스 범위
- **공공민원 전용.** 주민센터·구청 등 공공기관 방문 민원. 의료(병원·약국)는 범위 밖.
- **배포:** GitHub 저장소 → Vercel 자동 배포. 누구나 링크로 접속해 쓸 수 있다.
- **AI:** OpenAI API(크레딧 결제)로 음성 인식, 정리·되묻기, 음성 출력을 처리한다. API 키는 Vercel 서버 함수에만 둔다.
- **저장:** 사전 작성 내용은 사용자 휴대폰(로컬)에만 저장한다. 서버에는 저장하지 않는다.
- **안내 범위:** 민원 종류를 판단하지 않는다. 준비물·자격도 안내하지 않는다. 말한 내용과 관련 있을 수 있는 **기관 연락처만** 확인된 목록에서 안내해 간접적으로 돕는다. 찰떡의 핵심은 판단이 아니라 **대필**이다.
- **사용 방식:** 앱을 켜고 말만 하면 된다. 선택 단계 없이 바로 말하기로 시작한다.

## 해결하려는 문제
- 민원인은 무엇을 신청해야 하는지 모른 채 방문하고, 창구에서 할 말을 다 못 한 채 돌아서서 "아! 이거 말 못했는데!"를 겪는다.
- 담당자는 용건을 파악하기까지 같은 질문을 반복한다.
- 공공 민원의 AI 도입(국민신문고 대화형 AI, 민원 서류 자동 요약·분류)은 대부분 기관 쪽 도구다. 민원인 쪽에서 말을 정리해 주는 도구는 드물다.
- 정보취약계층은 기기 접근 수준은 일반 국민의 96.6%지만 이용 역량은 65.9%에 그친다(2025 디지털정보격차 실태조사).

## 대상 사용자
| 사용자 | 어려움 | 찰떡이 주는 것 |
|---|---|---|
| 고령층 | 화면 조작, 민원 용어 | 버튼 하나, 음성 안내, 큰 글씨 |
| 외국인 주민 | 한국어 설명 | 모국어로 말하면 한국어 요약 |
| 가족 대신 가는 보호자 | 누구의 일인지, 사정 전달 | 첫 문장에 대상자를 밝히는 요약 |
| 민원 담당 공무원 | 반복 질문, 불분명한 용건 | 5줄 이내의 같은 형식 요약 카드 |

## 핵심 원칙 (모든 기능에 적용)
1. **판단하지 않고 정리만 한다.** 자격 여부, 처리 결과, 준비물, 법률 해석을 내놓지 않는다.
2. **말하지 않은 내용은 넣지 않는다.** 요약의 모든 항목은 사용자가 한 말(원문)에 근거가 있어야 하며, 근거가 없으면 "미확인"으로 둔다.
3. **기관 안내는 확인된 데이터에서만.** AI가 기관이나 연락처를 만들어 내지 않는다. 출처·확인일이 있는 연락처 데이터에서 고른다.
4. **위기 상황 예외:** 생명·안전 위협이나 생계 위기 발언이 감지되면 119·112·129 안내를 먼저 띄운다.
5. **외부 전송을 알린다.** 첫 사용 시 "말한 내용은 정리를 위해 OpenAI로 전송되고, 저장은 내 폰에만 됩니다"를 알리고 동의를 받는다.
6. **사람이 처리한다.** AI가 대신 답하지 않는다. 담당자와의 대면 민원을 더 잘되게 돕는다.
7. **AI는 틀릴 수 있다.** 요약 화면과 창구 보여주기 화면에 "AI는 틀릴 수 있습니다"를 항상 표시한다.

## 성공 지표
- 접수 시간: 같은 대본으로 찰떡 사용 전후 비교
- 필수 항목 채움률: 템플릿 항목 중 채워진 비율
- 요약 정확도: 원문에 없는 내용이 들어간 항목 수 (목표 0)
- 담당자 판독 시간: 담당자가 요약 카드를 읽고 용건을 말하기까지 걸린 시간
- 되묻기 횟수: 민원 1건당 평균 3회 이하

# Core Features

## F1. 음성 입력 (첫 화면의 주인공)
- 첫 화면에서 "눌러서 말하기" 버튼을 가장 크게 보여준다. 누르는 동안만 녹음(push-to-talk).
- 말하기 어려운 경우를 위해 "글로 쓰기", "보기에서 고르기"를 버튼으로 함께 제공한다.
- 수락 기준: 안드로이드 크롬, iOS 사파리에서 Vercel 배포 주소(HTTPS)로 마이크 권한을 받아 녹음·업로드가 된다.

## F2. 관련 기관 연락처 안내 (간접 도움)
- 민원 종류를 판단·확정하지 않는다. 핵심은 판단이 아니라 대필이다.
- 연락처는 대화 중에는 보여주지 않는다. 사용자가 요약을 확인("맞아요")한 **최종 결과물**을 보고, 관련 있을 수 있는 기관의 연락처만 확인된 데이터(F8)에서 골라 "참고 연락처"로 출력한다.
- 부분 수정으로 요약이 바뀌면, 바뀐 최종 결과물을 기준으로 연락처를 다시 고른다.
- 효과: 민원인이 잘못된 창구로 가더라도, 미리 연락처로 확인할 수 있어 창구 직원이 다른 곳으로 안내하는 시간이 줄어든다.
- 수락 기준: 확인된 최종 요약을 기준으로 창구 보여주기 화면에 참고 연락처가 표시되고, 연락처는 데이터에 있는 것만 나온다.

## F3. 되묻기 대화 (핵심)
- 되묻기 항목을 몇 개로 정해 둔다(`data/slots.json`): 누구의 일인지(본인·가족), 용건, 원하는 것, 관련 날짜·기한, 궁금한 점.
- 사용자가 이미 말한 항목은 되묻지 않는다. 아직 나오지 않아 정보를 더할 수 있는 항목만 되묻는다.
- 질문 수는 상황에 따라 0~3회. 충분하면 바로 요약으로 넘어간다.
- 빠른 답 버튼에는 항상 **"해당 없어요", "잘 모르겠어요", "직접 말할게요"**를 함께 둔다(유도 방지).
- 수락 기준: LLM 응답이 JSON 스키마를 통과하고, 실패 시 1회 재요청 후 쉬운 말 오류 안내.

## F4. 원문 근거 검증
- 각 요약 항목은 `evidence`(사용자 원문 인용)를 가진다. 원문에 근거가 없으면 `unknown` 처리.
- 서버 함수에서 2단계로 처리: (1) 정리 (2) 검증(원문에 없는 내용 제거). 
- 사용자는 요약 화면에서 "내가 한 말 보기"로 원문을 확인할 수 있다.

## F5. 요약 확인과 부분 수정
- 요약을 큰 글씨로 보여주고 읽어준다.
- 틀린 항목만 눌러 그 항목만 다시 말하거나 고칠 수 있다(처음부터 다시 하지 않음).
- "맞아요"를 누르면 폰에 저장(F9).

## F6. 담당자용 요약 카드
- 5줄 이내, 굵은 고딕체, 짧은 문단.
- 구성: ① 누구의 일 (예: "어머니(본인 아님)의 기초연금 신청 건") ② 현재 상황 ③ 요청 ④ 미확인 항목 ⑤ 물어볼 것.
- 외국어로 말했더라도 카드는 한국어.

## F7. 창구 보여주기 모드
- 전체 화면, 가로 전환 가능, 최대 글씨. 담당자가 한눈에 읽는 화면.
- QR: 요약 텍스트를 QR 안에 직접 담는다(서버 URL 아님).

## F8. 기관 연락처 데이터
- 기관·연락처는 **확인된 데이터(JSON)에서만** 골라 보여준다(F2). 전화 걸기 버튼 제공.
- 데이터 항목: 기관명, 전화번호, 안내 범위, 출처 URL, 확인일.
- 초기 데이터 예: 기초연금 등 복지 → 보건복지상담센터 129, 국민연금공단 1355, 거주지 주민센터 / 일반 민원 → 정부민원안내콜센터 110, 거주지 주민센터.
- 준비물·자격은 안내하지 않고 "자세한 내용은 위 기관에 상담하세요"로 연결한다.

## F9. 폰 로컬 저장
- 확인된 요약을 IndexedDB에 저장. 목록 보기, 다시 열기, 지우기. 기본 7일 뒤 자동 삭제.
- 수락 기준: 오프라인에서도 저장된 요약과 창구 보여주기 모드가 열린다.

## F10. 외국어 지원
- 사용자 언어로 질문·안내, 요약 카드는 한국어. 시연 언어 1~2개(팀이 선택).

## F11. 위기 상황 안내
- LLM 응답의 `crisis` 필드 + 키워드 목록 이중 감지 → 119·112·129 안내 화면을 먼저 표시.

## F12. AI 오류 가능 고지
- 요약 확인, 창구 보여주기(참고 연락처 포함) 화면에 "AI는 틀릴 수 있습니다"를 항상 표시한다.

## F13. 장애 대응과 예시 체험
- AI 연결 실패, 사용량 초과, JSON 오류마다 쉬운 말 안내를 띄운다.
- AI 없이 흐름을 체험하는 예시 시나리오 2개를 제공한다(시연 실패 대비).

## 제외 (이번 구현 범위 아님, 제안으로만 소개)
보호자에게 문자 보내기, 준비물 안내, 민원 결과 저장·다시 보기, 키오스크 버전, 청각장애인 자막, 수어 인식, 정부24·국민신문고 연동.

# Technical Architecture

## 시스템 구성
```
[휴대폰 PWA] --HTTPS--> [Vercel]
   │ IndexedDB에 저장      ├─ 정적 프론트엔드 (React + Vite)
   │                       └─ 서버리스 함수 /api/*  ──> OpenAI API
   │                            ├─ /api/transcribe  (음성 인식)
   │                            ├─ /api/turn        (정리·되묻기 + 원문 검증)
   │                            ├─ /api/tts         (질문 음성)
   │                            └─ /api/contacts    (최종 요약 → 참고 연락처)
GitHub (main 브랜치 push → Vercel 자동 배포, PR마다 미리보기 배포)
```

| 프론트엔드 | React + Vite, Tailwind CSS, vite-plugin-pwa |

| QR | `react-qr-code` |

## API 규격
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/transcribe` | 음성(짧은 녹음 단위) → `{text, language}` |
| POST | `/api/turn` | `{history[], slots}` → `TurnResult` |
| POST | `/api/tts` | `{text, language}` → audio |
| POST | `/api/contacts` | 확인된 최종 `SummaryCard` → 관련 태그 판정 → 데이터에서 고른 참고 연락처 목록 |

- 서버는 상태를 저장하지 않는다(stateless). 대화 상태는 폰이 들고 있다가 매 요청에 함께 보낸다.
- 오류 응답은 `{code: "AI_UNAVAILABLE" | "RATE_LIMITED" | "BAD_JSON", message_ko}` 형식으로 통일해 쉬운 말 안내에 쓴다.

## LLM 응답 스키마 (`TurnResult`)
```json
{
  "slots": {
    "whose_matter": {"value": "어머니 (가족 대신)", "evidence": "엄마 기초연금 신청하려는데"},
    "purpose":      {"value": "기초연금 신청 방법 문의", "evidence": "기초연금 신청하려는데 뭐가 필요한지"},
    "desired":      {"value": null, "evidence": null},
    "date":         {"value": null, "evidence": null},
    "question":     {"value": "필요한 것이 무엇인지", "evidence": "뭐가 필요한지 모르겠어요"}
  },
  "questions_to_ask": ["대신 가서 신청해도 되나요?"],
  "next_question": "언제까지 해결하고 싶으세요?",
  "quick_answers": ["이번 주 안에", "급하지 않아요", "해당 없어요", "잘 모르겠어요", "직접 말할게요"],
  "ask_count": 1,
  "done": false,
  "crisis": false
}
```
- 검증 단계: `evidence`가 사용자 원문에 실제로 있는지 서버에서 문자열 대조 + LLM 검증. 없으면 값을 `null`(미확인)로.
- 이미 값이 있는 슬롯은 `next_question`으로 묻지 않는다.
- 대화 중(`/api/turn`)에는 연락처를 다루지 않는다.
- `/api/contacts`는 사용자가 확인한 최종 요약만 받아 정해진 태그 목록(예: `welfare`, `resident`, `general`) 중에서 관련 태그를 고르고, 그 태그의 연락처를 데이터에서 돌려준다. 태그는 민원 종류를 확정하는 값이 아니라 참고 연락처를 고르는 용도다.
- 프롬프트 금지 규칙: 민원 종류 판단·자격 판단·결과 예측·준비물 안내·법률 해석 금지, 기관·연락처 생성 금지.

## 보안·개인정보 요구사항
- 첫 사용 시 외부 전송 고지와 동의(동의 기록은 폰에만).
- 사전 작성 내용은 폰 IndexedDB에만 저장, 만료 시 자동 삭제, 사용자 삭제 기능.
- 서버 함수는 상태·내용을 저장하지 않으며, 민원 내용을 로그에 남기지 않는다(`console.log` 금지 규칙, 오류는 코드만 기록).
- OpenAI로 보내기 전 주민등록번호·전화번호 패턴 마스킹.
- API 키는 Vercel 환경변수에만, 저장소·프론트에 노출 금지.
- OpenAI 프로젝트 월 예산 한도 설정, 한도 초과 시 `RATE_LIMITED` 안내 + 예시 체험 모드로 전환.

# Development Roadmap

## Phase 0: 기반
- GitHub 저장소, Vercel 연결(미리보기 배포 확인), CLAUDE.md, 린터
- zod 스키마와 API 규격 확정, 되묻기 항목 목록(`slots.json`), `contacts.json` 작성(출처·확인일)
- 폰에서 Vercel 주소로 마이크 권한 확인

## Phase 1: 예시 데이터로 끝까지 연결
- 5개 화면 구현(디자인 시안 기준), 예시 시나리오 2개로 흐름 관통
- `/api/contacts` 구현 (최종 요약 입력 → 참고 연락처)

## Phase 2: OpenAI 연결
- `/api/transcribe`, `/api/turn`(정리 + 원문 검증), `/api/tts`
- 마스킹, 위기 감지, 오류 코드와 쉬운 말 안내

## Phase 3: MVP 완성
- 부분 수정, 내가 한 말 보기, 담당자 카드(5줄), 창구 보여주기 모드, QR
- IndexedDB 저장·목록·만료·삭제, 외부 전송 고지
- 외국어 1~2개, PWA 설치

## Phase 4: 현장 확인과 시연 준비
- 주민센터 직원 또는 공무원 경험자에게 담당자 카드를 보여 판독 시간·반응 확인, 형식 조정
- 어르신 2~3명 사용 테스트
- 시연 대본(전입신고, 복지 신청 대리, 외국어 1건, 위기 1건, 사용량 초과 1건)과 전후 비교 측정

# Logical Dependency Chain
1. 스키마·API 규격·되묻기 항목·연락처 데이터가 가장 먼저다.
2. Vercel 배포와 폰 마이크 권한을 Phase 0에서 확인한다.
3. 예시 데이터로 전체 흐름을 관통시킨 뒤 OpenAI 호출로 교체한다.
4. 음성 인식 → 정리 → 검증 → TTS 순서로 붙인다. 검증은 정리 결과 형식에 의존한다.
5. 담당자 카드·창구 모드·QR·폰 저장은 `TurnResult` 형식이 고정된 뒤 만든다. 참고 연락처는 최종 요약(`SummaryCard`)이 확정된 뒤에만 호출한다.
6. 외국어는 한국어 흐름이 안정된 뒤 언어 파라미터만 추가한다.

# Risks and Mitigations
| 위험 | 대응 |
|---|---|
| 말을 정리하며 사실이 왜곡되거나 없는 내용이 들어감 | 항목별 원문 근거 필수, 서버 검증, "내가 한 말 보기", 사용자 확인 |
| 빠른 답 버튼이 답을 유도 | "해당 없어요·잘 모르겠어요·직접 말할게요" 항상 포함 |
| 기관·준비물을 잘못 안내해 책임 문제 | 민원 종류 판단·준비물 안내 제외, 확인된 연락처 데이터에서만 안내 |
| AI 오답을 사실로 믿음 | "AI는 틀릴 수 있습니다" 상시 표시, 사용자 확인 단계 |
| 창구 직원이 요약을 읽지 않음 | 5줄 굵은 카드, 현장 반응 확인 후 형식 조정 |
| OpenAI 사용량 초과·장애 | 월 예산 한도, 쉬운 말 안내, 예시 체험 모드 |
| 서버 함수 요청 크기·시간 제한 | 짧은 녹음 단위 업로드, 응답 길이 제한 |
| 외부 전송에 대한 이용자 우려 | 첫 사용 고지·동의, 마스킹, 서버 미저장 |
| 고령층 발음으로 인식 오류 | 부분 수정, 빠른 답 버튼, 글로 쓰기 대안 |
| 범위 확장으로 일정 지연 | 제외 목록 고정 |
